# Пользовательский аудит EIRVEN 1.7.3 r34

Дата: 12 августа 2026 года. Сборка: `r34-mobile-lan`.

## Итог

Причина недоступного хоста в r33 подтверждена в исходниках: сервер уже слушал `0.0.0.0`, но Windows Firewall не настраивался, а QR не различал Wi‑Fi и виртуальные адаптеры. В r34 исправлены оба дефекта.

## Проверки от лица пользователя

| Сценарий | Результат |
| --- | --- |
| VPN является системным маршрутом, рядом есть активный Wi‑Fi | QR выбирает Wi‑Fi `192.168.*`, VPN остаётся видимым запасным вариантом |
| Windows Firewall не готов | На экране красный блок с прямым действием: перезапустить ярлык и подтвердить UAC |
| Одновременно выбран VPN и заблокирован Firewall | Интерфейс показывает обе причины, а не скрывает вторую |
| Пользователь выбирает другой адаптер | Адрес, APK-ссылка и SVG QR обновляются вместе |
| Firewall готов | Появляется зелёный статус с именем интерфейса, IP и портом |
| Гостевая сеть изолирует клиентов | UI и документация прямо называют `AP/Client isolation` как настройку роутера |
| Мобильное приложение не видит ПК | Ошибка направляет в зелёную диагностику на ПК и предлагает проверить Wi‑Fi вместо VPN |

## Автоматическая проверка

- Python: `87 passed`.
- Playwright CLI + реальный Chromium: пользовательский desktop-flow «Firewall error → VPN → обновление → Wi‑Fi ready → QR» пройден.
- JavaScript syntax: desktop и mobile passed.
- Репозиторный clean-install preflight: passed.
- APK: ZIP integrity passed; manifest `versionName=1.9.2`, `versionCode=10902`, `usesCleartextTraffic=true`; подпись и сертификат совпадают с r32/r33.
- Сервер запускается с bind `0.0.0.0`; middleware отдельно проверен для частного клиента и APK без pairing-кода.

Среда сборки не является Windows-машиной и не может физически применить правило Windows Firewall или подключить настоящий телефон. Поэтому PowerShell-контракт проверен тестами и исходным сценарием, а окончательная физическая проверка — сканирование QR на Windows — остаётся обязательным при приёмке.

## Если после r34 хост всё ещё недоступен

При зелёном статусе EIRVEN и правильном Wi‑Fi IP остаётся внешняя причина: VPN или изоляция клиентов роутером. Отключи VPN на обоих устройствах, используй не гостевой SSID и отключи `AP isolation` / `Client isolation` для домашней сети.
