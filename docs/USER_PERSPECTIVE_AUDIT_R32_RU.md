# Пользовательский аудит EIRVEN 1.7.2

Дата: 12 августа 2026 года. Сборка после исправлений: `1.7.2 · r32-mobile-ux`.

## Итог

В исходной поставке Android APK не мог работать с приложенным сервером: он обращался к `/api/mobile/*`, которых в сервере не было, а сервер слушал только `127.0.0.1`. Базовая проверка реального процесса возвращала `404` на `/api/mobile/status`. Это был блокирующий дефект, а не проблема настройки пользователя.

После исправлений desktop и Android используют один совместимый протокол. Подключение выполняется по адресу и отдельному коду из **Настройки → Телефон**. Код обязателен для мобильных маршрутов из домашней сети, а остальные API с другого устройства закрыты.

## Найдено и исправлено

| Важность | Что видел пользователь | Причина | Исправление и проверка |
|---|---|---|---|
| Блокирующая | APK не подключался ни по одному адресу | В сервере отсутствовали мобильные API, bind был только на loopback | Добавлены mobile status/video API, LAN-bind и экран подключения; реальный HTTP-прогон успешен |
| Критическая | После открытия сервера в сети можно было бы случайно раскрыть весь desktop API | Не было границы между локальным UI и телефоном | Частная сеть + отдельный код + allowlist mobile-маршрутов; public IP, desktop API и неверный код получают отказ |
| Высокая | Цифры и английские слова в голосовом ответе пропадали | TTS получал неподготовленные цифры/латиницу | Нормализация времени, процентов, температур, версий, URL, чисел, латиницы и сокращений; регрессионные тесты прошли |
| Высокая | Конец длинного ответа мог не прозвучать | Ограниченная очередь выбрасывала старые фрагменты | Очередь речи не теряет фрагменты; длинные предложения заранее делятся на короткие части |

| Средняя | Запрос про мобильное приложение путался с Telegram | Оба сценария определялись общими словами «телефон/мобильный» | Нативное приложение и Telegram теперь различаются; ответ ведёт в правильный раздел настроек |

## Проверено от лица пользователя

### Desktop-интерфейс

- Открытие **Настройки → Телефон** и появление адреса, кода и статуса готовности.
- Потоковый ответ, в котором финальное SSE-событие приходит без `\n\n`.
- Долгий запрос: кнопка меняется на «Остановить», остановка возвращает «Ответ остановлен.».
- Ввод следующей команды во время ответа: текст остаётся в поле после остановки.
- Невалидные сетевые ответы преобразуются в понятный пользовательский текст.

### Android-интерфейс

- Ручной ввод адреса без протокола и кода подключения.
- Переход от pairing-экрана в приложение после успешного статуса.
- Потоковый ответ без финального разделителя.
- Остановка зависшего ответа кнопкой `■` и сохранение следующего черновика.
- Ошибка задач показывает «Не удалось загрузить задачи» и предлагает повторить.
- Озвучка больших ответов отправляется на сервер частями, а воспроизведение имеет тайм-аут.

### Озвучка

Регрессии проверяют, что в подготовленном для синтеза тексте не остаются немые цифры или латинские слова. В частности прогнаны:

- «Wi‑Fi 6 работает на 42%.»;
- «Python 3.12, VS Code и OpenAI API.»;
- «Встреча в 14:30, на улице −5°C.»;
- «Открой https://openai.com и экспортируй MP4 в 1080p.».

## Ограничения проверки

Управляемый облачный браузер Playwright был запущен, но платформа заблокировала переход к локальному `127.0.0.1` (`ERR_BLOCKED_BY_CLIENT`). Обходить эту границу через другой браузерный рантайм небезопасно, поэтому пользовательские сценарии прогнаны на настоящих HTML/JS-клиентах в DOM-среде с потоковыми ответами и ошибками сети. Это проверяет кнопки, состояния, тексты и логику, но не является пиксельным снимком локального окна.

В этой Linux-среде нет Android-эмулятора, физического микрофона, динамика, Windows desktop и установленных пользовательских Ollama-моделей. Поэтому не заявляется как проверенное:

- субъективное качество тембра/интонации на реальном динамике;
- распознавание речи конкретного микрофона и шумоподавление конкретного телефона;
- фактические клики по Windows-приложениям, Telegram Web и Яндекс Музыке;
- содержательное качество генерации конкретной локальной модели на железе владельца;
- установка APK поверх старой версии: исправленный APK подписан новым тестовым ключом, поэтому старую сборку нужно удалить.

## Короткий ручной smoke-test перед публикацией

1. На Windows запустить `INSTALL EIRVEN AI.cmd`, закончить onboarding и убедиться, что открывается `Настройки → Телефон`.
2. Удалить старый APK, установить `EIRVEN-Mobile-1.9.0-r32-debug.apk`, подключить оба устройства к одной частной Wi‑Fi сети.
3. Ввести адрес и код, отправить текстом «Скажи: Wi‑Fi 6, OpenAI API, 42 процента, встреча в 14:30» и прослушать весь ответ.
4. Отправить заведомо долгую команду, набрать вторую, остановить первую кнопкой `■` и убедиться, что черновик сохранился.
5. Проверить голосом по одной команде из таблицы выше и подтвердить реальные side effects глазами.
