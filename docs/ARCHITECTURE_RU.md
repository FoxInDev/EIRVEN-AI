# Архитектура EIRVEN

## Принцип

Источник истины для desktop/web действий — **наблюдаемое состояние интерфейса**, а не длинные зашитые сценарии конкретных сайтов.

## Контуры

### Voice daemon

Слушает микрофон, обнаруживает речь, распознаёт русский текст и пропускает команду только после wake-name. Voice state публикуется UI и desktop-сфере.

### Reliability Router

Front-door арбитр r22. Определяет владельца команды до запуска старых fast-path:

1. instant / простые ответы;
2. атомарное приложение или системное действие;
3. compound app action;
4. текущая страница/раздел;
5. media action;
6. long-horizon mission;
7. модель как fallback.

### UI observation + autonomous workflow

Собирает Windows UI Automation дерево, выбирает видимый affordance, действует и снова наблюдает состояние. Search и navigation выполняются как state-machine, чтобы не вводить один и тот же запрос бесконечно.

### Mission Engine

Хранит длинную задачу как граф подзадач с зависимостями и типизированными артефактами. Commit-узлы не повторяются автоматически после фактического side-effect.

### Runtime ownership

Одновременно может существовать несколько фоновых работ, но физические GUI-действия проходят через единого foreground-owner/desktop-lock. Новая интерактивная команда отзывает незавершённый foreground workflow.

### Verification

После каждого действия проверяется изменение состояния. Для отправок, корзины, процессов и других side-effects действует single-shot подход.

### Video Editor

Видеокоманды перехватываются до desktop/media-маршрутов, чтобы «склей видео» не превращалось в управление проигрывателем. `VideoEditor` ведёт отдельный манифест активного проекта, проверяет и нумерует прямые файлы из корневой папки `video`, собирает безопасный FFmpeg-план и передаёт рендер в тяжёлую очередь `TaskManager`.

План допускает только типизированные операции; модель не получает возможность формировать произвольную shell-команду. Перед рендером исходники повторно сверяются по размеру и декодируемости, после рендера итог снова открывается FFmpeg. Новые файлы не входят в активный манифест автоматически. Принятие переносит источники в `video_archive`, итог — в `video_results`, а предыдущие результаты остаются ревизиями.

### Local API и UI

FastAPI обслуживает localhost UI и внутренние endpoint'ы. Интерфейс — HTML/CSS/JS с liquid-glass сферой. Пользовательская история, настройки и task-state хранятся локально в SQLite.

## Обновления

Update checker обращается к GitHub Releases публичного репозитория. Токен в дистрибутив не зашивается. При наличии `GITHUB_TOKEN` в окружении он может использоваться только для запросов к GitHub API.
